# 継ぎ方の決まりを測る

```bash
python3 tools/sim/chain_length.py        # 既定（12枚で打ち切り）
python3 tools/sim/chain_length.py 16     # 打ち切りを変える
```

標準ライブラリだけで動く。README 第8段階の数字はこれで出した。

## 難易度＝ランダムに置いた敵1体のマスを通る最長パスの平均

敵を討つには敵マスを通る鎖が要り、その鎖の威力は枚数で決まる。だから
**「その敵にどれだけ通せるか」がそのまま難易度**になる。

盤面は通常どおり 8行×6列＝48マス。隣接は上下左右だけ。相は均等に敷く（階層の
初期盤面を作る `_fillInitial` が `_spawn(even: true)` を使うため）。2000面で
1回ぶんとし、種を変えて5回繰り返して振れ幅も出す。

**12枚で打ち切る。** 守りの上限は 8 で、威力 9 あればどの敵も討てる。12枚まで
届けば討ち切れるので、それ以上の長さはゲームの上で差にならない。打ち切りを
上げると長い鎖を編める決まりほど値が伸び続け、比較にならなくなる。

## 測り方を間違えた話

最初は「継げる隣マスの割合」で測った。**これは当てにならない。** 3色の盤面では
巡回でも2色の交互でも次に置ける相は1種類（盤面の 1/3）なので、局所的には差が
出ない。ところが**鎖ごとに良い方を選べること自体が長さを押し上げる**ので、
最長パスで測ると差が出る。この取り違えで一度決まりを緩めすぎている
（README 第8段階）。

## 速さ

継ぎ方の判定は差分で回している。並び全体を毎回組み直すと DFS が遅すぎる。
`verify()` が、並び全体で判定する素直な実装と総当たりで突き合わせていて、
走らせるたびに先頭で検算する。**ここが食い違ったら数字は信用できない。**

## 決まりを足すとき

`Chain.can_push` に分岐を1つ足し、`verify()` の `full_ok` にも同じ決まりを
素直な形で書く。両方書かないと検算にならない。

# 1本の潜りで浴びる痛手を見積もる

```bash
python3 tools/sim/damage.py
```

階層の中身は `lib/game/dungeon.dart` をそのまま読む。手で書き写すと、階層を
いじったときに黙って古くなる。README 第9段階の表はこれで出す。

## 痛手＝生きている敵の攻撃力の合計 × その階層に使った手数

敵は毎ターン殴ってくるので、階層あたりの痛手は**どれだけ手間取ったか**で決まる。
討ち取ればその敵のぶんは止まるので、早く討つほど安い。

手数は2通りで見積もり、**実際はこの間に収まる**とみなす。

- **ゆるい** … その階層の手数（体力の合計 × 3 + 2）の6割を使う。手探りで打つ側
- **きつい** … 体力の合計ぶんの鎖 ＋ 立て直しの2手。これより速くは討てない

どちらも「敵は順に落ちるので、平均して攻撃力の半分が生きている」とみなす。
氷雨の回復と盾は入れていない（どちらも編成しだいなので、素の見立てに足す）。

# 同じ相が底に溜まるかを測る

```bash
python3 tools/sim/clump.py
```

2色の盤面で「ランダムな1マスを通るいちばん長い鎖を消す」を 40 手重ねて、
下2段の**死にマス**（3枚の鎖がどう引いても通らないマス）の割合と、下2段の
敵に通せる鎖の長さを出す。README 第23段階の表はこれで出した。

交互の決まりでは、同じ相の固まりはどの鎖も通れない。鎖は色の混ざった場所
ばかり消すので、固まりだけが残って沈んでいく。補充の決まり
（`Board.refill` の、真下と同じ相を降りにくくする `stackDamping`）を変えたら
ここで測り直す。`STACK_DAMPING` を `board.dart` と揃えること。

**完全な探索ではない。** 鎖の長さは片側へ伸ばし切ってから反対側へ伸ばすだけで、
控えめに出る。決まり同士・補充同士を比べるための物差しで、絶対値は
`chain_length.py` のほうを見ること。
